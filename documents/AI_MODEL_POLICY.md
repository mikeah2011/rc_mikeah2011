AI 模型与权限使用策略

目的

本文件记录本项目在不同阶段使用 AI 模型和运行时权限的策略，确保决策透明并可审计。

总体原则

- 在“规划与讨论”阶段优先使用能力更强的模型（示例：gpt-6-astra），以获得更准确、连贯的架构设计与高质量建议。
- 在“实现与代码变更”阶段优先使用成本/延迟更低的模型（示例：gpt-5-mini 或同等），以节省资源并保持可重复的代码编辑质量。
- 在模型选择、权限升级或自动化级别改变前，应将变更写入仓库文档并取得项目负责人的确认。

自动化/权限放开策略

1. 初始阶段（规划就绪前）
   - 模型：使用高能力模型进行设计与风险分析。记录在案后，得出明确的分批交付计划。
   - 权限：限制写操作与高权限命令（例如：远程推送、广域文件修改、生产环境访问）。仅允许创建或修改文档与本地临时目录的受控操作。

2. 计划磨合与签核
   - 当用户对计划表示“磨合 OK”并授权后：
     - 将“自动模式”调整为允许按批次执行受控实现（例如：创建 scaffold、添加 migrations、实现单一 API 路径）。
     - 逐步放开必要权限（例如：写入仓库、运行短时命令）但仍保持人类审批门槛用于关键步骤（如首次对外网络访问或部署脚本运行）。

3. 实施阶段（实现已批准）
   - 模型：优先使用资源消耗较小的模型完成常规代码编辑与测试。
   - 权限：按批次扩大权限范围。每次权限提升都应记录变更、理由与获得的批准人（至少一名项目负责人）。

记录与审计

- 所有模型选择、自动化级别与权限升降决议应写入仓库（推荐：documents/AI_USAGE.md 与本文件），并通过独立提交记录时间线。
- 每批次的提交信息需包含“使用模型”、“权限状态”、“执行者（AI/人）”和“变更简述”。

示例策略条目（提交模板）

- commit: feat(api): add notifications skeleton
- model: gpt-5-mini
- permissions: write-local-repo
- approver: @michael
- notes: scaffold generated in session temp dir; import into repo pending approval
